## 1. Objective

S.P.A.R.K. is being developed as a foundational capability for G.A.M.E. and is reactivated from its parked state on the earliest safe path to a G.A.M.E.-usable integration.

Speed is a priority, but it does not waive deterministic correctness, independent review, project authority boundaries, or the existing phase gates. Work that does not advance the critical path or independently improve reusable NIM engineering capability is deferred.

## 2. Meaning of the S.P.A.R.K. device

For this protocol, the **S.P.A.R.K. device** means the versioned, deployable S.P.A.R.K. capability that G.A.M.E. can invoke through the frozen host-adapter/protocol seam. It is a software capability, not a new hardware requirement.

The device may ultimately be delivered as an embedded Rust library, a standalone local service, or both with equivalent logical semantics. This protocol does not prematurely settle the still-open transport, serialization, deployment, or embedded-versus-service choice.

## 3. Non-negotiable authority boundary

G.A.M.E. remains authoritative for physical and economic world truth, including entity identity, logical game time, movement, inventory, money, trade, combat, resources, action legality, execution, and confirmed outcomes.

S.P.A.R.K. owns its deterministic causal, social, psychological, relationship, selected-memory, appraisal, goal, and pressure state. It returns advisory semantic behavior, speech, and gameplay-hook intents.

A S.P.A.R.K. `BehaviorIntent` is never an executable G.A.M.E. command. G.A.M.E. may validate, execute, reject, defer, or translate it. Only G.A.M.E.-confirmed outcomes return as authoritative observations.

The projects remain separately governed. Neither repository imports the other's governance, runtime authority, or internal ownership. S.W.A.R.M. runtime components are not introduced as dependencies by this protocol.

## 4. Convergence states

The joint work advances through these evidence-backed states:

1. **INTERFACE_RESERVED** — G.A.M.E. preserves stable entity identity, monotonic logical time, typed/scoped observations, advisory outputs, and confirmed-outcome seams. This is the activation state.
2. **ARCHITECTURE_READY** — S.P.A.R.K. V3-F01 is corrected, independently accepted, and frozen without reopening Phase 1.
3. **ENGINE_READY** — separately authorized Phase-2 rule/effect runtime implementation passes its acceptance matrix and independent review.
4. **DEVICE_CANDIDATE** — separately authorized Phase-3 work provides a versioned handshake/capability/message contract and a deployable S.P.A.R.K. endpoint or embedded surface.
5. **GAME_ADAPTER_CANDIDATE** — G.A.M.E. has a bounded adapter that maps its authoritative identities, logical time, observations, and confirmed outcomes without surrendering action authority.
6. **GAME_READY** — the paired pinned revisions pass deterministic replay, failure, rejection, capability, restart, and cross-platform acceptance evidence required by the bounded integration mission.

No state name is a substitute for its evidence, and no later state is claimed early.

## 5. Critical path

### Gate C1 — Close S.P.A.R.K. V3-F01

The first production-engineering action remains the bounded cohort-extraction/pre-wave-digest correction already identified by independent review.

- Architecture writer: Opus HIGH by default.
- Independent reviewer: Codex HIGH.
- Fable is reserved for non-convergence or a newly exposed foundational architecture defect.
- No Phase-2 Rust implementation begins before independent acceptance and freeze.

### Gate C2 — Implement and accept S.P.A.R.K. Phase 2

After separate Operator authorization, implement only the frozen Phase-2 rule/effect runtime and acceptance matrix. Preserve writer/reviewer separation and the existing deterministic, authority, canonical-identity, boundedness, and atomicity constraints.

### Gate C3 — Freeze the product integration contract

After Phase 2 is accepted and Phase 3 is separately opened, freeze the smallest versioned contract required by G.A.M.E.:

- protocol-version negotiation;
- profile and capability negotiation;
- stable external entity and affiliation references;
- monotonic logical execution point;
- typed and scoped host observations;
- advisory intent batches;
- host-confirmed outcomes and explicit rejection/defer reasons;
- idempotency, ordering, boundedness, compatibility, and fail-closed validation;
- deterministic canonical replay independent of transport.

The contract is defined independently of both projects' internal classes. Transport and deployment remain swappable around the same logical semantics.

### Gate C4 — Build the G.A.M.E. adapter thin slice

G.A.M.E. integrates one pinned, accepted S.P.A.R.K. artifact through a dedicated adapter. The first end-to-end proof uses the canonical causal sequence:

`drought -> food/affordability -> household exposure -> actor choice -> hunting -> wildlife decline -> neighboring-settlement feedback`

The proof must show that G.A.M.E. supplies physical/economic observations, S.P.A.R.K. supplies advisory causal/behavioral outputs, G.A.M.E. alone executes legal actions, and confirmed results deterministically feed back.

### Gate C5 — Prove deployable readiness

The paired integration must demonstrate:

- identical canonical results across standalone and embedded forms when both are supported;
- snapshot/restart and replay equivalence;
- duplicate, stale, malformed, unauthorized, unsupported-version, and out-of-order handling;
- bounded load/backpressure behavior;
- executable Linux evidence and the required Windows/Android canonical replay/digest parity before full three-platform equivalence is claimed.

## 6. Parallel work rule

G.A.M.E. may continue architecture and implementation that preserves the frozen seam and does not guess S.P.A.R.K. internals. S.P.A.R.K. work follows its phase gates. Integration-contract requirements and test fixtures may be prepared as working/non-production material before Phase 3, but production protocol/service code waits for Phase-3 authority.

NIM work should maximize useful task, role, model, and failure-hypothesis diversity within bounded concurrency and provider-health limits. Raw responses and provenance remain separate until synthesis. The completed NIM benchmark study is not rerun merely to enlarge a panel.

## 7. Cross-repository synchronization

Each convergence artifact records:

- its own repository commit;
- the exact external repository commit it relied upon;
- the claimed convergence state;
- evidence produced;
- unresolved blockers;
- the next gate.

One repository never silently advances the other's state. A claim becomes joint only when both repositories contain compatible pinned handoff records or an independently verified integration report identifies both exact commits.
