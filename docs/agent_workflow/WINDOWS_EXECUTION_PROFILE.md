## Local waiting and standing tool grants

Use the actor's native local execution interface for waits and shared-record checks. For an available local PowerShell session, use `Start-Sleep -Seconds 30` after closing file reads. This command creates no cross-session wake guarantee. Follow the shared recovery and immediate-notification procedure when local waiting is unavailable or fails.

**Desktop Commander.** Operator standing authorization, 2026-10-15 15:53 America/Chicago: "every agent is authorized to use it when it expedites or assists with task efficiency"; reaffirmed 2026-10-16: "Claude Code and Codex are both authorized to use Desktop Commander at their leisure for goal-oriented tasks." Every agent, including architects, builders, reviewers and authorized sub-agents, may choose it whenever it advances authorized work, without repeat permission for the tool choice. It supersedes the earlier kit restriction on Luna/Codex use (2026-10-08). Use native waits for idle delays, not Desktop Commander sleep or polling loops. Verify the connector's actual availability per session; the grant is not availability and availability is not permission. Tool choice changes no task authority, access control, independent review or reserved approval.

**Read/fetch.** The Operator's standing direction that agents have read-only GitHub access "in general" (2026-10-14) covers source inspection and `git fetch` needed for authorized project work. Fetch may update local Git objects and tracking metadata; it does not authorize merge, push, credential or configuration changes, or unrelated access. A narrower explicit rule of the project or task still applies until that project reconciles it; resolve an actual conflict once rather than asking per fetch. Set `GIT_NO_LAZY_FETCH=1` when a particular inspection must stay network-free.
